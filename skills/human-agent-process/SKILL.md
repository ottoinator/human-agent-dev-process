# Human-Agent Process

## Purpose

Apply a lightweight but evidence-driven software development process for humans
and AI agents working together.

## Operating Rules

- Classify task tier before implementation.
- Keep human owner decisions separate from agent execution.
- Ask before deciding goals, scope, risk, privacy, safety, cost, release, or
  irreversible changes.
- Scale gates with risk.
- Keep work scoped and evidence-based.
- Do not claim quality beyond available evidence.

## Quick Start

1. Restate goal, why, user, success signal, quality bar, and constraints.
2. Choose Tier 0, 1, 2, or 3.
3. Run only the gates required by tier and risk.
4. Implement the smallest coherent slice.
5. Verify with tests, review, runtime proof, or artifacts.
6. Deliver result, evidence, limits, and next action.

## Workflow

1. Read local instructions and relevant docs.
2. Identify owner decisions and open questions.
3. Choose roles or subagents for independent work.
4. Define acceptance criteria and evidence.
5. Implement.
6. Run QA.
7. Review for product fit, architecture, safety, and claim integrity.
8. Report honestly.

## Output Contract

Return:

- Tier and rationale.
- Owner questions or no-question reason.
- Gates used.
- Result.
- Verification.
- Claim status.
- Remaining risks.
